# Cost-conscious project continuity

- For implementation/"next task" requests, first read
  `docs/plans/NEXT_SESSION.md`, then the current README daily row and relevant
  master task rows. README is authoritative; never restart Completed work.
- On first use read the README v2 operating/budget rules; subsequently use targeted
  searches and changed sections instead of dumping README, SPEC, Pine or long logs.
- Check recorded usage, cash and renewal facts at each active session. Unknown
  values stay Unknown. Default extra paid usage is INR 0; project cash ceiling is
  INR 20,000 including fees. No purchase/recharge is authorized by the schedule.
- Show actionable in-session renewal/usage/budget alerts. Do not claim background
  notifications, exact token metering or account billing access without evidence.
- Batch dependent tasks with meaningful checks; never weaken trading/accounting
  verification to fit token checkpoints. Preserve the user's original Pine script.
- Preserve existing edits and market-hour paper observation. Use replay/test state
  for development, and keep manual practice, automated trials and formal burn-in
  evidence distinct. Calendar targets never waive acceptance requirements.
- Update README evidence/counts/next pointer, current daily-log row, actual receipts
  when supplied, and NEXT_SESSION handoff together. Never invent usage or trades.
- `docs/plans/README.v1.md` is immutable. Documentation-plan rows do not count as
  product task completions. Live-money tasks remain outside the funded paper plan.
